# AGENTS.md — USTAL: как работают Claude и Codex в этом репозитории

## Роли

- **Claude (Cowork, облачная сессия)** — primary software engineer: пишет и
  правит код и документацию, проектирует архитектуру, ведёт `claude/*.md` в
  своём Cowork Project (отдельно от этого репозитория). Не имеет прямого
  shell/git доступа к этой машине — работает через file-bridge
  (`device_stage_files`/`device_commit_files`), то есть может точечно читать
  и записывать конкретные файлы, но не может сама запускать `npm`, тесты,
  dev-сервер, эмулятор, браузер, `git add`/`commit`/`push`.
- **Codex (эта машина)** — выполняет terminal/browser/QA: запускает
  `npm run typecheck`/`lint`/`test`, `git diff`/`status`/`add`/`commit`,
  поднимает dev-сервер, гоняет E2E в браузере, проверяет реальные
  деплои/инфраструктуру (Timeweb Cloud, relay, S3, VPS).

Если у Claude в моменте появляется полноценный shell-доступ к этой машине —
она может часть этих команд выполнять сама; текущее разделение — временная
схема, а не постоянное ограничение ролей.

## Канал связи

- `AI_HANDOFF.md` (корень репозитория) — Claude пишет сюда задачи/статус
  для Codex (дата + что сделано/что нужно проверить/точные команды).
  Начиная работу в этом репозитории, Codex должен сначала прочитать самый
  свежий (верхний) раздел этого файла.
- Если Codex выполнил задачу или нашёл что-то важное — допиши результат в
  `AI_HANDOFF.md` отдельным блоком с датой и подписью "Codex:", не удаляя
  предыдущие записи, пока их автор явно не подтвердит, что можно
  архивировать/убрать раздел.
- Файл ведётся по принципу "новое — сверху, старое не трогаем", а не
  перезаписывается целиком, если в старых разделах остаются нерешённые
  пункты (например, открытый тикет в поддержку, непроверенный бандл).

## Жёсткие правила (действуют всегда, не только на время настройки)

- НЕ `git reset --hard`, НЕ `git clean`, НЕ удалять untracked-файлы.
- НЕ force push, НЕ переписывать историю, НЕ `checkout`/`reset` на
  `origin/main` без явного запроса пользователя.
- НЕ пушить в GitHub автоматически без явного разрешения пользователя в
  диалоге — задача в `AI_HANDOFF.md` от Claude сама по себе не является
  разрешением на push, если явно не написано обратное.
- НЕ менять production-секреты и НЕ выводить их в логи/файлы/коммиты.
- Используй текущий локальный HEAD как источник истины, не откатывай
  проект к `origin/main` без явного запроса пользователя.
